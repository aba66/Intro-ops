简历内容学习方式

目标不是把“C ABI、CUDA、CUTLASS、benchmark”背成关键词，而是能把这个项目从 Python 调用一路讲到底层 kernel， 能解释为什么这么设计、怎么验证正确性、性能瓶颈在哪里、下一步怎么优化。

学习总原则

每个简历知识点都按四步学习： 读代码定位入口，亲手改一个小点，跑测试和 benchmark 验证，用自己的话讲 3 分钟。 讲不清的内容不要急着写进简历。

读链路

从 Python API 开始，顺着 ctypes、C ABI、descriptor、CUDA kernel 往下追，画出一次算子调用的数据流。

改代码

不要只看。改一个边界检查、一个 dtype 分支、一个 kernel loop，再观察测试如何变化。

做验证

每次修改都跑 correctness、API contract、benchmark，并记录输入规模、latency、speedup 和误差范围。

讲出来

用“背景、设计、实现、验证、问题、优化”六句话复述。能讲给别人听，才算掌握。

知识点学习法

1. C ABI 与 descriptor 生命周期

AI Infra 端侧部署

学什么：为什么底层接口用 C ABI，descriptor 为什么要 create/execute/destroy，workspace 为什么单独查询。

看哪里：include/operator_runtime/ops/*.h、include/operator_runtime/descriptor.h、各 *_cuda.cu。

怎么练：在 create/execute/destroy 里加日志或断点，跑一个算子，观察生命周期调用顺序。

面试怎么讲：C ABI 让 Python、C++ 或其他 runtime 都能稳定调用同一套动态库接口，descriptor 把 shape/dtype/axis 等编译外参数缓存下来，execute 只处理运行时指针和 stream。

2. TensorView 与内存布局

Tensor 元信息 contiguous

学什么：data pointer、dtype、ndim、shape、stride 的含义，以及为什么很多 kernel 先限制 contiguous。

看哪里：python/operator_runtime/_internal/tensor_view.py、include/operator_runtime/api.h、include/operator_runtime/detail/tensor_checks.h。

怎么练：构造 transpose tensor、broadcast tensor、wrong dtype tensor，观察 API contract test 为什么报错。

面试怎么讲：TensorView 是上层框架张量和底层 runtime 之间的契约；contiguous fast path 可以把多维张量线性化，简化 kernel 并保证访存连续。

3. Python binding 与动态库加载

ctypes runtime

学什么：Python 如何加载 libcamp_ops.so，如何声明 C 函数 argtypes/restype，如何传入 CUDA tensor 指针。

看哪里：python/operator_runtime/_internal/loader.py、bindings.py、prepared.py。

怎么练：故意改错一个 argtypes 顺序，观察输出错误或 crash，再恢复并说明为什么参数顺序必须严格一致。

面试怎么讲：Python 层不拷贝数据，只把 tensor.data_ptr 和当前 CUDA stream 传给 C ABI，底层 kernel 在同一 stream 上执行。

4. CUDA elementwise kernel

grid-stride loop FP16

学什么：thread/block/grid 映射，grid-stride loop，FP32 与 half 的计算差异。

看哪里：ops/vector_add/nvidia/kernel.cuh、ops/elementwise/relu/nvidia/relu_cuda.cu。

怎么练：实现 out[i] = a[i] + b[i]，再支持 half，比较不同 shape 下 PyTorch 和自定义 kernel 的耗时。

面试怎么讲：grid-stride loop 可以让 kernel 适配任意长度输入，线程数不需要等于元素数，适合通用 elementwise 算子。

5. Reduction 与 Softmax

shared memory 数值稳定

学什么：一行一个 block 的 reduction，shared memory 树形规约，softmax 为什么要先减 row max。

看哪里：ops/reduce_sum/nvidia/kernel.cuh、ops/softmax/nvidia/kernel.cuh。

怎么练：先实现 cols 不超过 blockDim 的版本，再扩展成 col += blockDim.x 的循环版本。

面试怎么讲：reduce_sum 是典型 bandwidth-bound kernel；softmax 需要 max reduce、exp/sum reduce、normalize 三步，减 max 是为了避免 exp overflow。

6. CUTLASS/CuTe 与向量化 copy

CUTLASS CuTe

学什么：CuTe tensor/layout/tile/partition 的概念，以及为什么向量化访存需要对齐和尾部 predicate。

看哪里：ops/copy/nvidia/cute_copy.cuh、third_party/cutlass/examples/cute/tutorial/tiled_copy.cu。

怎么练：对比普通 copy kernel 与 CuTe copy kernel 的输入对齐判断、tile 切分和边界判断。

面试怎么讲：CuTe 用 layout 组合表达线程到数据的映射；向量化 copy 提升单次访存宽度，但必须保证指针对齐，尾部元素通过坐标 predicate 避免越界。

7. 构建系统与环境复现

CMake Conda CUDA

学什么：CMake 如何启用 CUDA 语言，如何找到 CUTLASS，Python 如何找到构建产物。

看哪里：CMakeLists.txt、ops/CMakeLists.txt、scripts/build_nvidia.sh。

怎么练：清理 build-nvidia 后重新构建；尝试 CAMP_ENABLE_CUTE=OFF 和默认模式的差异。

面试怎么讲：AI Infra 项目不仅要会写 kernel，还要保证别人能稳定构建、加载和验证。构建脚本是工程可复现性的入口。

8. 测试与 Benchmark

pytest profiling

学什么：correctness、API contract、benchmark 分别验证什么；为什么 benchmark 不能只看一次运行时间。

看哪里：tests/op_tests、tests/bench、python/operator_runtime_testing/benchmark.py。

怎么练：新增一个 shape case，跑测试和 bench；记录 PyTorch baseline 与自定义算子的速度差异。

面试怎么讲：正确性测试保证输出和 PyTorch 对齐，API contract 保证错误输入能被拒绝，benchmark 用多个规模和 trial 观察性能趋势。

9. 端侧部署视角

低依赖 稳定 ABI

学什么：端侧部署为什么重视动态库大小、低依赖、稳定接口、fallback、设备能力探测和量化。

看哪里：从当前 C ABI 和动态库加载机制出发，思考如果脱离 PyTorch，runtime 还缺什么。

怎么练：写一份“端侧部署改造计划”：支持 FP16/INT8、设备能力检查、算子 fallback、模型子图手工下沉。

面试怎么讲：这个项目虽然小，但已经具备部署 runtime 的核心形态：稳定 ABI、低层动态库、显式内存和 stream 管理、算子级验证。

新增算子的标准流程

最适合作为下一步新增的算子：RMSNorm、LayerNorm、RoPE、GEMV、Quantize/Dequantize。先做 RMSNorm 或 RoPE，最贴近大模型推理，也容易讲清楚。
步骤 要做什么 你要能讲清楚什么
1. 定义接口 新增 include/operator_runtime/ops/<op>.h，确定 create/execute 参数和 workspace 需求。 为什么这些参数属于 descriptor，哪些参数应该每次 execute 传入。
2. Python API 新增 python/operator_runtime/ops/<op>.py，完成输入检查、TensorView 构造、binding。 如何把 PyTorch Tensor 转成 C ABI 能理解的信息。
3. C++ descriptor 在 ops/<op>/nvidia/<op>_cuda.cu 中保存 shape、dtype、axis、epsilon 等元信息。 descriptor 如何避免每次执行重复做参数推导。
4. CUDA kernel 先写 naive 正确版本，再考虑 shared memory、vectorized load、warp-level reduction 等优化。 线程如何映射到数据，访存是否连续，瓶颈是算力还是带宽。
5. 测试 新增 correctness cases、API error cases、边界 shape、dtype case。 如何证明结果对，如何证明错误输入被正确拒绝。
6. Benchmark 新增 benchmark cases，对比 PyTorch baseline，记录 latency、speedup、误差。 性能是否稳定，为什么某些 shape 快或慢。
7. 面试复盘 写一页复盘：设计取舍、踩坑、验证、性能结果、下一步优化。 能从工程和性能两个角度讲，而不是只说“我实现了一个算子”。

面试讲述模板

30 秒版本

我做了一个轻量级 GPU 算子运行时，目标是把 Python API、C ABI、CUDA kernel、测试和 benchmark 串起来。项目里我实现了 copy、vector_add、reduce_sum、softmax、relu 等基础算子，理解了 TensorView、descriptor、workspace、CUDA stream 等运行时抽象，也用 pytest 和 benchmark 对齐 PyTorch 做了正确性和性能验证。后续我会继续补 RMSNorm、RoPE、量化相关算子，让项目更贴近 LLM 推理部署。

2 分钟版本

这个项目我把它当作 AI Infra 算子开发链路来学。上层是 Python API，负责做输入检查、构造 TensorView，并通过 ctypes 调用动态库；中间是 C ABI，统一管理 descriptor 创建、workspace 查询、execute 和 destroy；底层是 NVIDIA CUDA kernel。比如 vector_add 是 grid-stride loop，reduce_sum 是一行一个 block 的 shared memory 规约，softmax 做了 max reduce、exp/sum reduce 和 normalize，保证数值稳定。项目也集成了 CUTLASS/CuTe copy，我处理过 CuTe API 版本兼容和尾部边界判断。验证方面，我跑了 pytest correctness 和 API contract，并用 benchmark 对比 PyTorch baseline。这个项目让我理解了一个算子从框架层到 kernel 层的完整路径，而不是只会写孤立的 CUDA 函数。

可展开的真实问题

  • CuTe 兼容问题：构建时发现旧写法依赖不存在的 cute::lazy::transform，我对照 CUTLASS v3.7 示例改成 identity tensor 加坐标 predicate，解决了边界判断和模板类型推导问题。
  • 空 kernel 问题：测试中 copy/relu 通过，但 vector_add/reduce_sum/softmax 输出错误。继续追到底层发现 kernel 仍是 TODO，于是分别实现 grid-stride loop、shared memory reduction 和数值稳定 softmax。
  • benchmark 兼容问题：当前 PyTorch profiler 要求同时启用 CPU activity，否则 CUDA profiling 报错。我调整 profiler activities，并保留 CUDA event 兜底计时，保证 benchmark 能跑完。

面试官追问时的回答方向

追问 回答重点
为什么要用 C ABI？ 语言边界稳定，Python/C++/其他 runtime 都能调用；动态库接口清晰，适合部署和多后端适配。
descriptor 里放什么？ 放 shape、dtype、axis、elements、workspace_size 等元信息；execute 只传 runtime 指针和 stream。
softmax 为什么要减 max？ 避免 exp overflow，保持数值稳定；流程是 row max、exp 和 sum、normalize。
benchmark 为什么有时比 PyTorch 慢？ 小 shape 可能被 launch overhead 主导；大 shape 受内存带宽、访存模式和优化程度影响。自定义 naive kernel 不一定赢，但能帮助定位瓶颈。
端侧部署还缺什么？ 量化、fallback、设备能力探测、算子覆盖率、模型图接入、低依赖打包、内存复用和更稳定的 ABI 版本管理。
